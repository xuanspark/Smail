```powershell
Set-Location D:\Desktop\Smail
```

## 原有开发模式

```powershell
Set-Location D:\Desktop\Smail\backend
$env:SMAIL_ROOT = 'D:\Desktop\Smail'
go run . dev
```

末尾 `dev` 仍读取 `config/config.dev.json` 并启用项目原有开发行为，现在也会停用管理员重置通道。该文件可能使用另一份数据库，不应为解决权限问题直接切换过去。开发模式下不再使用 `SMAIL_ADMIN_CONTROL_PATH` 创建重置通道。

`SMAIL_ROOT` 必须是 `config/` 的父目录，不能设置成 `D:\Desktop\Smail\config`，否则会变成 `config/config/`。直接运行 `out/backend/` 下的程序或管理工具时也应显式设置该变量；默认可执行文件目录规则为独立正式部署保留，不自动猜测源码位置。

## 正式部署

- 移除 `--dev-disable-admin-reset`，不要以末尾 `dev` 启动。
- Windows 保持受保护命名管道及管理员客户端校验；Linux 保持受保护本机套接字及对端身份校验。
- 通道创建或运行失败仍会让正式后端启动失败或退出，不静默降级。
- 没有新增 HTTP、局域网或公网重置接口。
- 启动参数属于部署主机权限边界，不能由网页请求切换。不要把开发启动命令复制进正式服务配置。

开发模式不能用于验收真实管理员恢复功能；该功能需在对应系统的正式权限条件下单独验收。
