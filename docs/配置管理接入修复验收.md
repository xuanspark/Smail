## 原因

旧配置尚未迁移，管理器不能启用；原启动代码又把配置目录当成服务根目录传入加载器，重复拼接路径。只生成分区文件仍不足以修复，旧业务还需要正确读取新的数据库与证书引用。

迁移后发现另一个独立问题：备份列表读取使用了高风险回滚权限，现有会话的近期认证过期时返回 `403 / RECENT_AUTH_REQUIRED`。前端又把附属请求失败提升为整页不可用。

现在只有脱敏代次列表读取改用 `config.read`，普通用户仍被拒绝。回滚的三个操作均有自动测试确认近期认证要求没有放松。

## 后续开发启动

必须重新编译当前源码再启动，不能继续运行迁移前遗留的旧后端二进制：

```powershell
Set-Location D:\Desktop\Smail
powershell -NoProfile -ExecutionPolicy Bypass -File deploy/build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File deploy/start-dev.ps1 -Service backend
```

编译前先停止同名运行进程；同时只能有一个后端占用服务端口。目录整理后的运行文件为 `out/backend/smail-dev.exe`，启动脚本显式指定配置根目录 `backend/`。前端开发地址为 `http://127.0.0.1:15173`。

开发参数只停用本机管理员重置通道，不改用另一份数据库，不放宽线上接口鉴权。正式部署需移除此参数，保留 Windows 命名管道或 Linux 本机套接字保护。

## 其他旧部署的显式迁移

以下命令只适用于尚未迁移的旧部署，本机已迁移完成，不应重复执行：

```powershell
Set-Location D:\Desktop\Smail
& .\out\backend\smail-config.exe --root D:\Desktop\Smail\backend
# 先停止后端并备份配置目录，再执行以下命令。
& .\out\backend\smail-config.exe --root D:\Desktop\Smail\backend --apply
```

默认命令仅做旧字段检查，不是完整迁移预演；完整校验及备份迁移发生在 `--apply`。命令本身不检测运行中的后端，停机必须由部署人员确认。
