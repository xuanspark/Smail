## 应用改动

1. Socket 所有者检查改为先拒绝无效有效 UID，再进行宽类型比较，避免将当前 UID 缩窄后比较。
2. 终端设备号先限制在有符号 32 位范围，再显式还原其无符号编码并检查转换边界。不能直接拒绝所有负值，否则会破坏合法高位设备号。
3. `poll` 前验证文件描述符不超过有符号 32 位上界，已关闭文件的无效描述符立即拒绝。
4. 密码代理固定为 `/usr/bin/systemd-ask-password`，服务任务查询固定为 `/usr/bin/systemctl`。环境诊断也检查同一代理路径，不再从可变 `PATH` 找到另一程序。
5. 两处终端关闭显式记录忽略返回值的意图：授权失败仍拒绝；正常退出先取消并等待监视器结束，再关闭无业务写入缓冲的终端描述符。这不是修复两个已确认漏洞，也没有新增扫描忽略注释。

云服务器上的两个系统程序均属于 root，权限为 `0755`。固定路径是该 Linux/systemd 部署的依赖；其他发行版路径不同时不能无条件声称兼容。
