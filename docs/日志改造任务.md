# 日志存储与可视化改造

## 已确认需求

- 操作记录、配置审计、收发信记录写入独立 MySQL，邮件业务数据库不随之迁移。
- 设置导航在插件配置后增加日志入口，支持分类、时间筛选、分页与详情。
- 运行日志保存在 `log/运行日志`，按天写入；每周一压缩已经结束的自然周，停机后启动补做。
- 压缩后的运行日志仍可在后台查看；仅在压缩校验通过后替换对应明文文件。
- 配置审计展示操作者、时间、具体字段及修改前后值；秘密只显示配置状态。
- 旧配置审计幂等迁移并保留原文件，不伪造历史缺失的变更详情。
- 不自动删除历史记录；15 GB 是容量预算而不是容量保证。
- 配置仍在原有五个 JSON 文件中，日志连接保存在 `config.json`，密码加密保存。

## 验收边界

生产 MySQL 连接必须由部署者配置，不能猜测或复用其他项目的密码。未配置时保留旧审计路径并明确显示未启用，不能把 SQLite 或内存存储称为 MySQL 已启用。已配置后的写入故障必须可观察，不能无限排队或静默丢弃。
