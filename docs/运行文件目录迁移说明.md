# 运行文件目录迁移说明

## 需求确认

运行配置统一放在 `D:\Desktop\Smail\config`；`backend/config` 是 Go 配置管理源码包，不整体重命名或删除。运行日志继续放在 `test-log/runtime`，编译输出继续放在 `out`。

## 文件归属

```text
Smail/
├── config/                   # 忽略 Git 的本机运行文件
│   ├── config.json           # 当前启动使用的分区根配置
│   ├── smtp.json             # SMTP 分区
│   ├── email.json            # 邮箱策略分区
│   ├── ssl.json              # 证书引用分区
│   ├── plugins.json          # 插件配置分区
│   ├── config.dev.json       # 历史 dev 模式配置，不是当前启动配置
│   ├── config_mysql.json     # 保留的另一份配置，不自动启用
│   ├── config.json.legacy    # 历史配置原始备份
│   ├── smail_temp.db         # 当前账号及邮件数据库
│   ├── smail.db              # 另一份已有 SQLite 数据库，保留
│   ├── credential.key       # 凭据加密主密钥
│   ├── external-email-*.key  # 外部邮箱加密和指纹密钥
│   ├── dkim/                # DKIM 密钥及备份
│   ├── ssl/                 # TLS 证书、私钥及 ACME 资料
│   ├── migration-backups/   # 配置格式迁移备份
│   ├── backups-v2/          # 分区配置备份
│   └── transaction/         # 配置事务工作目录
└── backend/config/          # Go 源码、同包测试和原有说明文档
```

## 启动约定

- `deploy/start-dev.ps1` 设置 `SMAIL_ROOT=D:\Desktop\Smail`。程序使用 `SMAIL_ROOT/config` 读取和生成运行文件，不能把环境变量设置成 `config` 自身。
- 当前启动继续使用 `--dev-disable-admin-reset`，读取 `config/config.json`，不切换到 `config.dev.json` 或另一份数据库。
- 为保持已有插件安装路径，子进程工作目录仍是 `backend/`。初始化目录已改为基于 `SMAIL_ROOT`，不再向工作目录写入 `./config`。
- 直接运行编译程序或 `go run` 时也需要显式设置 `SMAIL_ROOT`。独立正式部署保留原有环境变量优先、可执行文件目录回退规则。
- 如果 `backend/config` 仍存在旧配置、主密钥或 SQLite 文件，开发启动脚本停止并提示先迁移，防止误初始化第二份账号库。

## 迁移和保护边界

1. 修改前提交中文检查点并推送，真实运行文件不进入 Git。
2. 停止并核实当前项目后端进程，前端保持运行。
3. 迁移前记录源码及运行文件清单和 SHA-256；运行文件另存一份本地回退副本到 `test-log/archive`。
4. 只迁移明确的运行文件，目标存在同名文件时拒绝覆盖；保留 Go 源码及说明文档，不删除旧空目录。
5. JSON、数据库、密钥及证书保持原始字节；分区配置的摘要和相对路径无需更改。
6. 迁移后逐一校验哈希，再启动后端并核对运行根目录、数据库及探活结果。
7. 根目录 `ssl/` 的人工输入证书、`backend/smail.db` 的原有空文件、历史测试配置不属于当前活动配置，不删除，也不冒充当前数据源。

本次是保留数据的目录迁移，不进行清库初始化。自动测试使用 `test-log` 下独立临时数据库；业务数据库仅做只读完整性和账号摘要校验。进程启动后的正常任务可能更新业务数据库，迁移字节校验应在重启前完成。
