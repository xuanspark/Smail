# Smail 插件开发说明文档

Smail 提供灵活、高隔离、安全的插件扩展架构。无论是编写垃圾邮件智能拦截器，还是对接第三方即时通讯平台（如企业微信、钉钉、Telegram、飞书）进行实时邮件推送，开发者均可通过插件体系无缝扩展系统能力。

---

## 1. 插件架构设计

### 1.1 独立子进程运行模式
- Smail 插件采用**独立操作系统子进程（Subprocess）**模式运行，而非脆弱的动态库链接（CGO 或 Go Plugin）。
- **优势**：
  - **故障彻底隔离**：任何插件发生内存泄漏或崩溃，绝不波及 Smail 主邮件服务的稳定运行。
  - **跨语言支持**：支持使用 Go、Python、Node.js、Rust 等任意可执行程序开发。
  - **嵌入式内置打包**：Smail 在编译发布时，通过 `hooks/bundle.go` 将官方核心插件直接内嵌于主二进制中，首次部署时自动解压释放。

### 1.2 标准 IPC 通信协议
- **数据通道**：主程序通过标准输入（`Stdin`）向插件管道发送任务指令，插件通过标准输出（`Stdout`）回传处理结果。
- **序列化格式**：每一帧交互均为换行符分隔的 **标准 JSON 字符串（JSON Lines）**。

---

## 2. 核心 Hook 钩子体系

Smail 在邮件流转的各关键生命周期定义了标准 Hook 点：

| 钩子名称 (Hook Type) | 触发时机 | 插件职责与能力 | 典型应用 |
| :--- | :--- | :--- | :--- |
| `email_receive_filter` | SMTP 接收邮件并解析后、落库存储前 | 可审查邮件头、发件人信誉、正文内容、附件哈希；可**拦截（Reject）**或**放行（Pass）** | 垃圾邮件过滤、内容违规检测 (`spam_block`) |
| `email_received_notify` | 邮件成功入库且分发至收件箱后 | 异步获取入库邮件详情与收件人信息，触发外部投递 | 微信公众号/企业微信推送 (`wechat_push`)、Telegram 机器人通知 (`telegram_push`) |
| `email_send_filter` | 用户提交发信请求、投递出站前 | 审查外发敏感信息、数据防泄密 (DLP)、外发配额监控 | 合规审计、敏感词拦截 |

## 3. 通信数据结构定义

### 3.1 邮件过滤 Hook (`email_receive_filter`)
#### 主程序输入至插件 (Stdin):
```json
{
  "hook": "email_receive_filter",
  "data": {
    "message_id": "<abcd.1234@example.com>",
    "from": "spammer@bad.com",
    "to": ["user@yourdomain.com"],
    "subject": "免费领取大奖",
    "content_text": "点击链接领取...",
    "content_html": "<p>点击链接领取...</p>",
    "client_ip": "1.2.3.4",
    "spf_result": "pass",
    "dkim_result": "none"
  }
}
```

#### 插件响应回主程序 (Stdout):
```json
{
  "action": "reject",
  "reason": "命中高危垃圾邮件关键词规则",
  "mark_spam": true
}
```
> 若允许放行，返回 `{ "action": "pass" }` 即可。

### 3.2 邮件通知 Hook (`email_received_notify`)
#### 主程序输入至插件 (Stdin):
```json
{
  "hook": "email_received_notify",
  "data": {
    "recipient": "admin@yourdomain.com",
    "sender": "partner@client.com",
    "subject": "关于项目合作推进的沟通",
    "received_at": "2026-10-19T10:00:00+08:00",
    "summary": "您好，附件为最新合同草案..."
  }
}
```

#### 插件响应回主程序 (Stdout):
```json
{
  "status": "success",
  "message": "已成功推送至目标渠道"
}
```

## 4. 最小插件开发示例 (Go 语言)

以下为使用 Go 语言实现的极简邮件通知插件核心源码：

```go
package main

import (
	"bufio"
	"encoding/json"
	"fmt"
	"os"
)

type HookPayload struct {
	Hook string                 `json:"hook"`
	Data map[string]interface{} `json:"data"`
}

type HookResponse struct {
	Status  string `json:"status"`
	Message string `json:"message,omitempty"`
}

func main() {
	scanner := bufio.NewScanner(os.Stdin)
	for scanner.Scan() {
		line := scanner.Bytes()
		if len(line) == 0 {
			continue
		}

		var payload HookPayload
		if err := json.Unmarshal(line, &payload); err != nil {
			continue
		}

		// 根据钩子类型处理业务
		switch payload.Hook {
		case "email_received_notify":
			subject, _ := payload.Data["subject"].(string)
			recipient, _ := payload.Data["recipient"].(string)
			
			// 执行通知业务（例如调用 HTTP Webhook）
			// sendWebhook(recipient, subject)
			_ = recipient
			_ = subject

			resp, _ := json.Marshal(HookResponse{
				Status:  "success",
				Message: "通知已推送",
			})
			fmt.Println(string(resp))

		default:
			resp, _ := json.Marshal(HookResponse{Status: "pass"})
			fmt.Println(string(resp))
		}
	}
}
```

## 5. 插件专属 UI 扩展与打包规范

如果插件需要在 Smail 设置中心展示可视化的配置表单（如 Telegram Bot Token 设置界面）：
1. **单文件内嵌 UI**：前端开发采用 Vite + SingleFile 插件（如 `plugins/telegram-ui/`），将 HTML、CSS、JS 完全内联编译为一个单独的 `index.html`。
2. **插件构建脚本**：使用项目自带的构建脚本执行批量编译：
   ```bash
   node deploy/build-plugins.mjs
   ```
3. **输出目录**：编译生成的跨架构插件可执行文件将统一放置在 `out/plugins/<os_arch>/`，并在打包时自动集成进发布包的 `plugins/` 目录中。
