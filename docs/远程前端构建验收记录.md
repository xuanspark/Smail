## 恢复工具整改

修改 `test/tools/build_frontend_review.py` 与 `test/deployment/test_frontend_build.py`。基线提交为 `4f5b05e`，已推送项目的 `smail` 远程；仓库没有 `origin` 远程，最初对此名称的推送失败后改用实际远程成功。

停止构建失败时先区分预检拒绝导致的单元不存在；其他异常记录为失败，并尝试终止该构建单元的残留进程。无论停止和终止操作是否超时，仍依次尝试恢复 MySQL、Scert，不再提前跳过恢复。单元名称限定为本工具生成的构建单元，不能传入业务服务名。父单元停止预算增加到 480 秒，以覆盖恢复路径的命令超时；保留 `finally` 与 systemd `ExecStopPost` 两层恢复。

构建硬上限从 960 MiB 调整为 896 MiB，Node 堆上限从 768 MiB 调整为 640 MiB；系统保留预算仍为 128 MiB。预检要求暂停服务后至少 1024 MiB 可用内存，失败则拒绝构建并恢复服务。此调整针对构建工作进程，不降低业务服务预算或密码计算参数。
