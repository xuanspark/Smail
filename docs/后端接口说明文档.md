# Smail 后端接口说明文档

本文档面向所有使用 Smail 的开发者、运维人员及第三方系统集成者，全面公开 Smail 当前版本的 HTTP Web API 接口规范、身份鉴权机制、数据传输格式与各模块调用方式。

---

## 1. 基础规范与公共约定

### 1.1 接口地址与协议
- **协议**：HTTP / HTTPS（生产环境推荐启用 HTTPS）
- **规范路径前缀**：所有规范接口统一以 `/api/v1/` 为前缀；系统同时向下兼容 `/api/` 别名。
- **数据传输格式**：所有 POST / PUT / PATCH 请求正文（Body）必须为 `application/json`；响应格式统一为 `application/json; charset=utf-8`。

### 1.2 统一响应结构
所有接口在 HTTP 状态码为 200 时，均返回以下统一 JSON 结构：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

- **code** (`int`): 业务状态码。`0` 表示操作成功；非 `0` 表示业务逻辑异常或失败。
- **message** (`string`): 操作结果提示或错误说明（中文）。
- **data** (`object` | `array` | `null`): 具体业务返回数据。

### 1.3 身份认证与安全机制 (Authentication & CSRF)
1. **会话认证 (Cookie)**：
   - 用户登录成功后，服务端会在响应头中写入会话 Cookie：`smail_session`（带有 `HttpOnly` 与 `SameSite` 策略）。
   - 随后的所有受保护接口依赖该 Cookie 进行状态鉴权。
2. **跨站请求伪造防护 (CSRF Token)**：
   - 对于所有的状态变更请求（POST、PUT、DELETE），客户端必须在 HTTP 请求头中携带：
     ```http
     X-CSRF-Token: <从初始化或登录响应中获取的有效Token>
     ```
3. **角色与权限模型**：
   - **普通用户 (Normal User)**：管理个人邮件、个人安全码、TOTP、客户端专属发信凭据、收信规则、联系人分组等。
   - **管理员 (Admin) / 超级管理员 (SuperAdmin)**：除普通权限外，还拥有系统级配置审计、用户账号生命周期管理、全站日志检索、域名解析与证书状态审查、数据库无感在线迁移等全局权限。

## 2. 基础与探活接口

### 2.1 服务健康探活
- **接口路径**：`GET /api/v1/ping`（兼容别名 `GET /api/ping`）
- **权限要求**：公开访问，无需认证
- **响应示例**：
  ```json
  {
    "code": 0,
    "message": "pong",
    "data": {
      "status": "healthy",
      "version": "V2.14.0"
    }
  }
  ```

## 3. 身份验证与会话管理 (Auth)

### 3.1 用户账号登录
- **接口路径**：`POST /api/v1/login`（兼容别名 `POST /api/login`）
- **权限要求**：公开访问
- **请求参数**：
  ```json
  {
    "username": "admin@example.com",
    "password": "YourStrongPassword"
  }
  ```
- **响应字段**：
  ```json
  {
    "code": 0,
    "message": "登录成功",
    "data": {
      "user_id": 1,
      "username": "admin@example.com",
      "is_admin": true,
      "require_2fa": false,
      "csrf_token": "3f81a7b..."
    }
  }
  ```
  > 若账号启用了二次验证（TOTP / Passkey），则 `require_2fa` 为 `true`，此时登录流程尚未完成，需调用 3.2 接口进行校验。

### 3.2 登录二次安全验证
- **接口路径**：`POST /api/v1/security/login/verify`
- **权限要求**：初次密码校验通过后的临时认证状态
- **请求参数**：
  ```json
  {
    "verify_type": "totp", 
    "code": "123456"
  }
  ```
- **响应结果**：二次验证通过后，下发正式的会话凭据。

### 3.3 退出登录 (Logout)
- **接口路径**：`POST /api/v1/logout`（兼容别名 `POST /api/logout`）
- **权限要求**：已登录用户
- **响应结果**：清除服务端会话并作废 Cookie。

## 4. 账号多重安全与多因素凭据 (Security & 2FA)

### 4.1 TOTP 双因素认证管理
- **获取 TOTP 绑定秘钥与二维码**：`GET /api/v1/security/totp/setup`
  - 返回 TOTP 秘钥 `secret` 与用于扫码绑定的标准 `otpauth://` URI。
- **验证并启用 TOTP**：`POST /api/v1/security/totp/enable`
  - 请求参数：`{ "code": "6位动态验证码" }`
- **停用 TOTP**：`POST /api/v1/security/totp/disable`
  - 请求参数：`{ "password": "当前用户密码" }`

### 4.2 Passkey / WebAuthn 硬件通行密钥
- **获取注册挑战参数**：`GET /api/v1/security/webauthn/register/begin`
- **完成密钥注册**：`POST /api/v1/security/webauthn/register/finish`
- **删除已绑定的安全密钥**：`DELETE /api/v1/security/webauthn/keys/:key_id`

### 4.3 安全恢复码 (Recovery Codes)
- **查看/生成新安全恢复码**：`POST /api/v1/security/recovery-codes/generate`
- **使用恢复码重置认证**：`POST /api/v1/security/recovery-codes/verify`

### 4.4 外部安全备用邮箱绑定
- **发送绑定验证码**：`POST /api/v1/security/external-email/send-code`
  - 请求参数：`{ "external_email": "backup@gmail.com" }`
- **确认绑定外部安全邮箱**：`POST /api/v1/security/external-email/confirm`
  - 请求参数：`{ "external_email": "backup@gmail.com", "code": "123456" }`

## 5. 协议专属发信凭据与系统授权 (Credentials)

Smail 严格遵守权限最小化原则，杜绝直接暴露主账号密码用于第三方发信，提供细粒度的独立授权。

### 5.1 客户端专属发信授权码 (Client Credentials)
用于 Foxmail、Outlook、手机邮件客户端等 SMTP/IMAP/POP3 专属接入。
- **获取当前用户凭据列表**：`GET /api/v1/credentials`
- **生成专属客户端授权码**：`POST /api/v1/credentials`
  - 请求参数：
    ```json
    {
      "client_name": "Mac Mail",
      "service_type": "smtp"
    }
    ```
  - 响应结果返回一次性高强度授权密码（明文仅显示一次）。
- **修改/启停专属授权**：`PUT /api/v1/credentials/:id/status`
- **删除专属授权**：`DELETE /api/v1/credentials/:id`

### 5.2 系统通知与外部服务发信授权 (System Notification Credentials)
专为系统监控、告警、微服务等第三方系统发信设计。
- **获取系统通知凭据列表**：`GET /api/v1/credentials/system-notifications`
- **创建自定义服务发信授权**：`POST /api/v1/credentials/system-notifications`
  - 请求参数：
    ```json
    {
      "service_name": "用户注册中心",
      "sender_display_name": "系统自动通知",
      "rate_limit_per_hour": 100
    }
    ```
- **查看与重置服务发信密钥**：`POST /api/v1/credentials/system-notifications/:id/reveal`

## 6. 邮件收发与管理 (Email Operations)

### 6.1 邮件列表查询
- **接口路径**：`GET /api/v1/email/list`（兼容别名 `GET /api/email/list`）
- **查询参数**：
  - `box_type` (`string`): 邮箱分类：`inbox`（收件箱）、`sent`（已发送）、`draft`（草稿箱）、`trash`（垃圾箱/已删除）。
  - `page` (`int`): 当前页码，从 1 开始。
  - `page_size` (`int`): 每页条数，默认 20。
  - `keyword` (`string`): 搜索关键字（匹配发件人、收件人、主题）。

### 6.2 邮件详情查看
- **接口路径**：`GET /api/v1/email/detail`（兼容别名 `GET /api/email/detail`）
- **查询参数**：`id` (`int`) 邮件主键 ID。
- **响应数据**：包含邮件正文 HTML/纯文本、完整的发件人显示名、原始时间戳、DKIM/SPF 校验结果状态以及附件元数据列表。

### 6.3 邮件发送
- **接口路径**：`POST /api/v1/email/send`（兼容别名 `POST /api/email/send`）
- **请求参数**：
  ```json
  {
    "to": ["recipient@domain.com"],
    "cc": [],
    "bcc": [],
    "subject": "邮件主题",
    "content_html": "<p>邮件正文内容</p>",
    "content_text": "邮件正文纯文本",
    "attachments": ["temp_file_token_1"],
    "sender_name": "自定义发信人名称"
  }
  ```

### 6.4 邮件草稿保存与更新
- **接口路径**：`POST /api/v1/email/draft`
- **接口路径（更新）**：`PUT /api/v1/email/draft/:id`

### 6.5 邮件删除与批量清理
- **接口路径**：`POST /api/v1/email/delete`（兼容别名 `POST /api/email/delete`）
- **请求参数**：
  ```json
  {
    "ids": [101, 102],
    "permanent": false
  }
  ```
  > `permanent: false` 移入废纸篓；`permanent: true` 物理彻底粉碎删除。

### 6.6 附件上传与安全下载
- **上传附件**：`POST /api/v1/attachments/upload`（使用 `multipart/form-data` 上传）
- **下载附件**：`GET /api/v1/attachments/download/:attachment_id`

## 7. 智能规则引擎与过滤器 (Rule Engine)

### 7.1 收信过滤规则列表
- **接口路径**：`GET /api/v1/rules`
- **响应数据**：包含规则优先级、触发条件（发件人包含、主题正则、域名匹配等）与执行动作（直接标记垃圾、自动归档指定分组、自动转发出站等）。

### 7.2 新建/编辑收信规则
- **接口路径**：`POST /api/v1/rules` / `PUT /api/v1/rules/:id`

### 7.3 发件人黑白名单管理
- **接口路径**：`GET /api/v1/email/sender-filters`
- **添加黑白名单**：`POST /api/v1/email/sender-filters`
  - 请求参数：`{ "email_or_domain": "spammer.com", "filter_type": "blacklist" }`

## 8. 联系人与邮件分组 (Groups & Contacts)

- **获取邮件分组列表**：`GET /api/v1/groups`
- **新增邮件分组**：`POST /api/v1/groups`
- **修改分组名称**：`PUT /api/v1/groups/:id`
- **删除分组**：`DELETE /api/v1/groups/:id`

## 9. 用户账号生命周期管理 (User Management)

> **注**：本模块接口仅限拥有管理员（Admin）或超级管理员权限的用户访问。

### 9.1 用户账号列表
- **接口路径**：`GET /api/v1/admin/users`
- **查询参数**：`page`, `page_size`, `search`

### 9.2 创建全新账号
- **接口路径**：`POST /api/v1/admin/users`
- **请求参数**：
  ```json
  {
    "username": "newuser",
    "domain": "example.com",
    "password": "UserInitialPassword",
    "quota_mb": 1024,
    "is_admin": false
  }
  ```

### 9.3 编辑与修改账号
- **接口路径**：`PUT /api/v1/admin/users/:user_id`
- **可更新属性**：用户限额、启用/禁用状态、管理员权限、个人显示名等。

### 9.4 删除账号
- **接口路径**：`DELETE /api/v1/admin/users/:user_id`
- **说明**：支持选择级联清理用户邮件数据或归档封存。

## 10. 系统运维、审计与数据库管理 (System & Migration)

### 10.1 系统日志查询
- **接口路径**：`GET /api/v1/admin/logs`
- **参数支持**：`log_type`（邮件收发日志、系统审计日志、登录安全日志）、`level`（info/warn/error）、时间范围筛选。

### 10.2 域名 DNS 与 SSL 证书状态检查
- **接口路径**：`GET /api/v1/admin/domain/status`
- **检测项目**：MX 记录、A/AAAA 记录、SPF 记录、DKIM 公钥匹配、DMARC 策略有效性、SSL 证书有效天数。

### 10.3 跨数据库无感在线迁移 (Database Migration)
Smail 独创的三合一单数据库热切换与迁移接口：
- **发起数据库全量迁移**：`POST /api/v1/database/migrations`
  - 请求参数：
    ```json
    {
      "target_engine": "mysql", 
      "target_dsn": "user:pass@tcp(127.0.0.1:3306)/smail_db?charset=utf8mb4&parseTime=True&loc=Local"
    }
    ```
- **查看迁移实时进度与回执**：`GET /api/v1/database/migrations/status`
