## 缺陷定位与最小修复

旧候选在 `/var/tmp/smail-review-runtime-20260921-063341/` 的 MySQL → PostgreSQL 迁移中返回 HTTP 409，提示数据库数据校验未通过。目标数据复制已提交，但配置切换被拒绝；失败源库、目标库和日志均保留，没有通过重试覆盖既有目标。

只读原生 SQL 初步比较只能看到失败响应后可能变化的操作日志与会话时间，不能据此认定并发写入是原因。随后使用新建的最小 SELECT 权限账号、只读事务和生产摘要函数进行 Go 驱动级诊断，定位到 `verification_cleanup_state.lease_token`：MySQL 的定长字符读取结果与 PostgreSQL `BPCHAR` 填充后的驱动值不一致。

最终只读诊断位于 `/var/tmp/smail-review-diagnostic-20260921-070712/`。只输出表名、列名、类型、数量和差异标记，不输出行内容、凭据或摘要原文。诊断有意以非零退出报告差异，不算通过的验收。最初两类启动失败也保留：`PrivateTmp` 隐藏执行路径，以及隐藏正式家目录后驱动默认客户端证书路径不可访问。修正仅以本轮目录只读覆盖可见路径，正式 `/opt/smail` 仍被遮蔽；没有关闭 TLS、解锁原测试账号或改变正式服务。各次诊断账号均已锁定。

`backend/services/dbmigration/portable_data.go` 在行扫描后按**实际源引擎和列元数据**处理填充：

- 仅 MySQL `CHAR`、PostgreSQL `BPCHAR` 删除右侧 ASCII 空格填充。
- 复制与校验共用同一读取路径，支持 PostgreSQL 作为源库的反向迁移。
- 不裁剪前导空格、制表符、换行或非断行空格。
- 不改变 VARCHAR、TEXT、BLOB、BYTEA 或 SQLite 的值，即使 SQLite 列声明为 CHAR。
- NULL 与空字符串、实际令牌内容变更、变长文本或二进制尾部差异仍须区分。
- 全表复制、行数与摘要校验、失败不切配置等保护全部保留。
