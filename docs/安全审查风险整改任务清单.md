- 测试不得删除工作区真实配置或数据库；应使用临时目录和测试专用配置。
- 本次不保留旧密码算法兼容逻辑，不执行旧算法与新算法双轨校验；已有账号通过统一的密码重置或重新初始化流程设置新密码。

# 三、P0：上线阻断项

## SEC-001：禁止 SMTP 587 在 STARTTLS 前认证

- **状态**：[ ] 未开始
- **风险等级**：P0 / 高风险
- **关联问题**：SMTP 明文认证导致凭据泄漏。
- **关联文件**：
  - `server/listen/smtp_server/smtp.go`
  - SMTP 认证和 STARTTLS 相关测试文件

### 整改要求

1. 587 端口在 TLS 建立前不得声明 `AUTH` 能力。
2. 只有 STARTTLS 成功后才允许 `AUTH PLAIN`、`AUTH LOGIN` 或其他认证方式。
3. 移除或关闭允许不安全认证的配置。
4. 465 端口继续使用隐式 TLS，不与 587 的明文升级逻辑混用。
5. 对 TLS 协商失败、重复认证和 STARTTLS 降级行为增加测试。

### 验收标准

- 明文连接执行 `EHLO` 时只返回 `STARTTLS`，不返回 `AUTH`。
- 未执行 STARTTLS 直接发送认证命令时，服务器拒绝认证。
- STARTTLS 成功后重新执行 `EHLO`，才返回认证能力。
- 认证失败时日志中不包含密码或密码编码值。
- 增加自动化测试，覆盖成功、失败和降级场景。

### 复审建议

使用隔离测试端口执行 SMTP 对话验证，并保存不含凭据的协议输出。

## SEC-002：删除 SMTP 明文密码日志

- **状态**：[ ] 未开始
- **风险等级**：P0 / 高风险
- **关联问题**：Debug 日志输出认证密码。
- **关联文件**：
  - `server/listen/smtp_server/action.go`
  - 其他 SMTP 认证日志调用点

### 整改要求

1. 删除所有用户名和密码同时输出的日志。
2. 不记录明文密码、Base64 密码或完整 AUTH 报文。
3. 只记录认证方式、脱敏账号、结果、远端地址和追踪信息。
4. 搜索整个仓库，确认没有其他认证密码日志。
5. 检查现有日志配置，避免调试模式绕过脱敏逻辑。

### 验收标准

- 使用成功和失败认证各执行一次，日志中均不存在密码原文。
- 搜索源代码和测试输出，不存在密码格式化日志。
- 日志中账号已按需要脱敏。
- 认证失败日志不会回显用户输入的敏感字段。

### 复审建议

使用固定测试账号进行验证，但不要把实际密码写入命令历史、报告或 Git。

## SEC-003：保护初始化接口并限制初始化网络边界

- **状态**：[ ] 未开始
- **风险等级**：P0 / 高风险
- **关联问题**：攻击者可能在管理员之前抢先完成初始化。
- **关联文件**：
  - `server/listen/http_server/setup_server.go`
  - `server/listen/http_server/https_server.go`
  - `server/controllers/setup.go`

### 整改要求

1. 初始化接口必须要求一次性随机初始化令牌。
2. 默认初始化服务只监听 `127.0.0.1` 或受控管理地址。
3. 初始化成功后立即使令牌失效。
4. 初始化完成后，`/api/setup` 必须永久拒绝重复初始化。
5. 增加来源限制、失败次数限制和速率限制。
6. 初始化操作必须记录审计事件，但不得记录密码、私钥内容或数据库凭据。
7. 对数据库、管理员、域名、SSL 路径等字段进行服务端校验，不能仅依赖前端。

### 验收标准

- 无初始化令牌不能调用初始化接口。
- 令牌只能使用一次，重复使用失败。
- 非本机来源无法完成首次初始化，除非管理员明确配置了受控入口。
- 初始化完成后再次调用接口返回拒绝结果。
- 端口扫描或未授权请求不会泄漏初始化配置细节。

### 复审建议

在隔离环境启动一个全新实例，分别验证无令牌、错误令牌、重复令牌、跨来源请求和初始化成功后的重复调用。

## SEC-004：禁止明文 HTTP 承载登录会话

- **状态**：[ ] 未开始
- **风险等级**：P0 / 高风险
- **关联问题**：HTTP 模式下可能窃听登录请求和会话 Cookie。
- **关联文件**：
  - `server/listen/http_server/http_server.go`
  - `server/listen/http_server/https_server.go`
  - 会话 Cookie 配置
  - `server/config/config*.json`

### 整改要求

1. 生产模式强制 HTTPS。
2. HTTP 只允许安全跳转或 ACME 挑战，不加载完整业务路由。
3. HTTPS 下的会话 Cookie 必须设置 `Secure=true`。
4. 保持 `HttpOnly=true`，合理设置 `SameSite`。
5. 添加 HSTS，并确认代理转发场景下协议判断正确。
6. 避免由于错误的反向代理头导致服务误判为 HTTP 或 HTTPS。

### 验收标准

- 通过 HTTP 访问登录页面时只能获得安全跳转或明确拒绝。
- HTTP 不接受登录请求、不返回完整业务页面、不设置可用会话 Cookie。
- HTTPS 响应中的会话 Cookie 包含 `Secure` 和 `HttpOnly`。
- HTTPS 页面不存在混合内容。
- HSTS 只在确认 HTTPS 部署正确后启用。

## SEC-007：统一密码哈希与凭据验证机制

- **状态**：[ ] 未开始
- **风险等级**：P1 / 中风险
- **关联问题**：MD5、固定盐、无独立随机盐。
- **关联文件**：
  - `server/utils/password/encode.go`
  - 用户创建、登录、修改密码流程
  - 数据库用户表结构

### 整改要求

1. 统一使用 Argon2id 作为用户密码的唯一哈希算法，不再保留 MD5、固定盐、bcrypt、scrypt 或其他旧算法的运行时兼容分支。
2. 每个密码使用独立的密码学安全随机盐，并保存经过评审的算法参数和版本。
3. 将密码处理集中到统一的密码服务，例如 `PasswordService`，统一提供密码策略校验、哈希和验证能力。
4. 登录、用户改密、管理员重置、初始化管理员密码和其他用户密码验证入口必须调用同一个密码服务，不允许各业务模块自行拼接或比较哈希。
5. 第三方配置验证必须复用统一的凭据校验流程、输入规范化、超时、错误分类和脱敏日志规则。
6. 需要向第三方服务发起连接的 SMTP、API 或其他密钥不能使用不可逆密码哈希保存，应使用受控加密存储，并通过统一的 `CredentialValidator` 完成配置有效性验证。
7. 密码比较和第三方凭据校验应避免时序侧信道；所有失败响应不得泄露账号、配置或凭据是否存在的额外信息。
8. 不在日志、错误响应或审计记录中记录密码、第三方密钥、令牌或完整认证报文。
9. 对已有旧算法密码不提供兼容登录；发布前完成账号密码重置或强制重新设置密码，并提供管理员可审计的处理结果。

### 验收标准

- 新创建和重置后的用户密码均使用 Argon2id，数据库中不存在新写入的 MD5 或其他旧算法哈希。
- 每个用户的盐值不同，算法参数和版本可以被服务端正确解析。
- 登录、初始化、用户改密和管理员重置使用同一个密码服务，并对相同输入给出一致的成功或失败结果。
- 旧算法密码不会被兼容登录；没有完成密码重置的旧账号按明确策略被拒绝并引导设置新密码。
- 第三方 SMTP、API 等配置使用统一的凭据验证流程；验证成功的配置与实际运行时连接使用相同的规范化和校验规则。
- 第三方密钥不会以明文或不可逆哈希形式保存，日志、错误响应和审计记录均已脱敏。
- 密码哈希参数经过性能和部署环境验证。
- 错误密码、无效第三方配置和不存在的凭据不会产生可用于枚举的差异化错误信息。

## SEC-009：增加统一 CSRF 防护和状态修改方法限制

- **状态**：[ ] 未开始
- **风险等级**：P1 / 中风险
- **关联问题**：Cookie 会话状态修改接口缺少统一 CSRF 防护。

### 整改要求

### 验收标准

- 无 CSRF Token 的跨站状态修改请求被拒绝。
- 错误 Origin 被拒绝。
- GET 请求不能执行有副作用的操作。
- 正常前端请求自动携带并校验 Token。
- 登录、退出和 Token 失效流程经过验证。
