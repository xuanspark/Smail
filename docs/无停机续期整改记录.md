## 代码变更

`deploy/nginx/renew_certificate.py` 使用 `SMAIL_ACME_DNS_PROVIDER` 指定 DNS 服务商，不再调用 `stop/start nginx`，不允许配置缺失时退回停机验证。依据线上实际使用证书判断是否临近到期，而不是依据签发目录中的候选证书。ACME 正式服务地址显式指定，命令超时为 600 秒，保留密钥复用及互斥控制。

`deploy/nginx/deploy_certificate.py` 与续期入口共用同一进程锁。候选、旧证书和旧私钥首先保存到 root 专属快照，再对同一份快照进行系统信任链、五个域名、服务用途、剩余至少七天有效期以及私钥匹配验证。普通续期只允许复用已有密钥，密钥轮换另行验收。

发布后执行 `nginx -t`、平滑重载，并实际检查 443 和 8002 的系统信任及证书指纹。失败时恢复旧文件、重新重载并检查旧指纹。文件已经一致但线上仍使用旧证书时，会补做重载，避免上次任务在写文件后被中断导致永久不同步。校验快照和回退副本保留在 `/var/backups/smail-certificate-*`，不会自动删除。

候选 service 移除了 `ExecStopPost` 启动 Nginx 的旧钩子，支持 `/etc/smail/acme-dns.env`，总超时 720 秒。原有 96/128 MiB、禁用交换空间、CPU 和任务数限额保留。`acme-dns.env.example` 只包含空白凭据示例，不是可直接启用的正式授权。

历史维护窗口工具 `test/deployment/renewal_drill.py` 增加旧续期脚本摘要限定，拒绝将原先针对停机实现的演练用于新的 DNS 实现。

修正 `test/tools/remote_review.py`：项目审查上传目录使用 `0700`，不再把已保护的目录改回 `0755`。已通过真实上传后的远程权限检查确认。

## 启用 DNS 续期前的门槛

1. 确认 `example.com` 实际 DNS 服务商及专用最小权限授权。凭据只保存在远程受保护文件，不在聊天、仓库、普通文档或日志中传递；示例采用阿里云不代表已获得该账号授权。
2. 使用全新、独立的 ACME 测试账号完成五个域名的真实 DNS-01 挑战，验证 TXT 创建、传播及清理，不以已有授权缓存代替挑战。
3. 验证 DNS 拒绝、超时与清理失败期间两个站点及邮件服务仍可用，正式证书和私钥保持不变。
4. 在受保护备份和持续探测下同步安装新的续期脚本、部署脚本和 service，再完成正式签发及七个入口的新指纹检查。不能只替换其中一个脚本：旧续期脚本在持锁期间通过子进程调用部署脚本，与新版本共用锁的执行方式不同，混用会导致锁冲突。
5. 接入真实外部续期失败、证书临近到期告警，完成一次失败告警送达及恢复验证，再将无停机续期列为验收通过。

截至本轮结束，线上仍使用旧续期定时任务，证书有效期至 2026-12-16。保留旧任务不代表批准未来停机维护窗口；必须在进入到期续期窗口前完成 DNS 迁移。发布验收清单中的其他业务、安全、容量和恢复门槛继续有效。
