## 实现边界

`backend/utils/clientip` 接收请求和 `http.trustedProxyCidrs`，先检查真实 TCP 来源是否位于显式配置的可信网段。只有可信来源的单个 `X-Forwarded-For` 头可参与解析；不将 `X-Real-IP` 或 `Forwarded` 当作回退来源。

多级代理链从右向左检查，停在首个非可信地址，不使用任意客户端可添加的最左侧地址。重复头、非法或空链元素、带端口或区域标识的地址、未指定地址、多播地址、超长头和超过 32 跳的链均回退到真实连接来源。IPv4 映射 IPv6 先规范化，避免同一来源形成多个限流键。配置中包含非法网段时也不信任转发头。

控制器 `remoteIP` 和 `loginRemoteHost` 共用同一解析结果，因此验证码签发、验证、恢复和登录限流对来源的理解一致。账号维度限流保持不变。没有修改 `RemoteAddr`，首次安装来源限制、原有 TLS 模式识别和本机管理 IPC 边界保持不变。

上线时应仅配置真实代理网段。本服务器上游为 `127.0.0.1:8002`，可使用 `127.0.0.1/32`；仅在确实使用 IPv6 回环上游时再加入 `::1/128`。不得为了兼容而配置 `0.0.0.0/0` 或 `::/0`。Nginx 必须继续使用 `proxy_set_header X-Forwarded-For $remote_addr` 覆盖客户端头，而非无条件信任已有转发链。若以后接入 CDN，需要重新确定代理信任边界并验收，不能直接扩大网段。

更正真实 IP 可能使部署前按回环地址绑定的待验证挑战失效，应重新发起验证；不得为迁移兼容而跳过 IP 绑定。该变更本身不声称已经撤销所有旧会话或完成管理员恢复验收。
