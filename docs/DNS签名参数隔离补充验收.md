## 修复与反例

原请求函数直接向传入的 `url.Values` 写入公共字段和签名。
第一次请求结束后，参数对象残留 `Signature`；再次使用它时，签名原文把旧值也包含进去。
预先带有旧签名的参数会从第一次调用开始不匹配。

现在为每次请求复制参数及其切片，复制时排除 `Signature`，之后只修改独立副本。
随机数仍由密码学随机源生成，每次请求重新生成时间戳；没有改动签名算法、TLS 校验、超时或跳转策略。

原始失败日志：

- `dns-signature-before-20260921.log`：带旧签名参数的三次请求均不匹配，且调用者参数被改写。
- `dns-signature-before-v2-20260921.log`：增加干净参数复用反例，第二次起签名不匹配；两组反例均失败。

原始日志没有删除或覆盖。验证器按 UTF-8 字节独立编码，不调用生产的百分号编码函数。
固定输入由独立 Python 标准库计算，向量文件为 `dns-signature-vector-20260921.json`。
向量中的密钥、签名都是公开测试样本，不是真实云凭据；它不是服务商发布的官方测试向量。

## 协议参考与告警边界

从阿里云官方 Go SDK 仓库的 `sdk/auth/rpc_signature_composer.go` 取得参考实现，核对 RPC 签名字段、签名前移除旧签名及编码流程。
这仅证明该 SDK 实现使用相应签名方式，不证明当前 API 必须使用该算法，也不代表服务商禁止迁移其他签名协议。
本轮没有擅自把 HMAC-SHA1 替换为其他算法，亦不将其作为密码存储或证书签名算法使用。
