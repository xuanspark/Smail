## 已实现入口

完整构建并部署二进制，不覆盖配置和数据库：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File deploy/deploy-runtime.ps1
```

完成运行数据迁移后，启动前后端：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File deploy/start-dev.ps1 -Service all
```

后端启动总是先完整编译、部署和校验。单独启动前端会校验当前源码与部署产物，不允许搭配过期后端。缺少迁移后的配置、账号库或密钥时拒绝启动，不会创建另一份空库。

构建收据保存在 `out/build-state.json`，不混入部署根目录。已有程序被覆盖前备份至 `out/deployment-history/`。历史前端编译目录归档至 `out/build-history/`，不删除生成物，也不将历次散列资源重复嵌入新程序。

## 构建与测试互斥

Windows 下，`deploy/build.ps1` 与 `node test/run.mjs backend` 共用工作区命名互斥量。构建计算指纹、归档嵌入资源之前就获取锁，测试从调用 Go 到退出始终持锁。遇到冲突立即拒绝执行并给出中文提示，不能继续移动资源或使用历史产物冒充成功。

锁标识由源码目录生成：同一登录会话内，不同工作区可并行；同工作区必须串行。正常退出和进程异常结束均不需要删除锁文件。不同 Windows 登录会话、直接调用 `go test`、直接调用 Vite 或单独插件构建不在该锁的保证范围内，不能与完整构建并发执行。

```powershell
# 前端、部署回归和后端依次执行，记录统一进入 test-log。
node test/run.mjs all -p 2 ./...

# 只检查构建互斥及后端参数转发。
node test/run.mjs deployment
```

新增的 PowerShell 文件使用 UTF-8 BOM，以便 Windows PowerShell 5.1 正确解析中文提示；JavaScript、Go 和 JSON 不因此添加 BOM。

前端热更新只更新源码开发页面，不会自动重编嵌入前端的主程序。源码修改完成后，仍须通过标准完整部署/重启入口刷新 `yunx-test`，不能只刷新浏览器就宣称运行包已更新。
